# OpenBot config on the Computer

Use this skill on the authenticated Grok Bot Computer. OpenBot supervises the selected native host, normally `/opt/sand/sand-host/host-main.cjs` or legacy `/home/box/sand-host/host-main.cjs`. It does not patch the Mac client. Read [reference.md](reference.md) for exact disk/API contracts and [the coordinated update guide](../../docs/updating.md) before updating either runtime.

Official uses stock server/Temporal delivery and Grok quota. Temporal is vendor managed; OpenBot does not deploy that cloud service. Custom uses the owned local BOX/OpenBot runtime and its saved provider route. A failed Custom request never falls back to Official/Temporal. `openbot-mode` is authority; a retained catalog does not imply Custom. Official preserves the plan, credentials and saved local engine.

One owned loopback process on `127.0.0.1:9280` serves the panel, `/api/*` and Custom `POST /v1/chat/completions`. Mutations that change mode/wrap/tunnel use `DesiredState` and reconcile. Never adopt a foreign listener, start a second hop or launch a tokenless native host.

## Inspect before changing

Read the selected host/data paths, literal mode, current catalog/default, bot pins/efforts, pauses, routines, engine/follower policies and installed source receipt. Inspect owned process identity and any pending operation/reload receipt. Keep credentials and conversation data private; show secret shapes only with `<stored locally>`.

Preserve existing accounts/IDs, model assignments, histories, routine switches, MCP/ACP settings, selected engine and network identity unless the user requested that change. Do not remint identities or copy server-owned bots to BOX merely to repair routing. Profile/roster health is not actual send or delivery proof.

Use JSON for a configuration-only edit when mode is Custom, the selected host has `/* openbot-stock-wrap */`, `/api/state` succeeds and the published `openbot-ui.pid` identifies the owned live service. Plan/secrets/maps/log/injection/bot-model edits are read on the next request. A request already in flight keeps its route. Otherwise reconcile; do not bounce the host for ordinary catalog edits.

## Install or update source

Use a fresh reviewed checkout of the public distribution or your own fork. Keep it separate from live data, credentials, private backups and any old recovery repository history; the exporter binds this recipe to the selected repository:

```bash
gh repo clone nickkostik/openbot-community /tmp/openbot-source
OPENBOT_SRC=/tmp/openbot-source bash /tmp/openbot-source/install.sh --bot-mode
```

For an existing checkout, use its actual path/commit. Follow the printed `OPENBOT_BOT_INSTRUCTION`; poll status at most twice in a Bot turn. Direct installation omits `--bot-mode`. First install starts in Official; an update retains existing desired state. Use `OPENBOT_TUNNEL=off` only when local-only exposure is intended. The repository may require an authenticated GitHub login. The installer requires stable Node 22.13+ within 22.x or 24+, rejects earlier 22.x/23.x, and verifies TypeScript stripping plus built-in fetch/WebSocket. It preserves system Node, validates a private cached runtime or checksum-verified staged fallback before activation, and refuses an invalid stage. [Runtime prerequisites](reference.md#supported-node-runtime).

Quickstart begins with read-only `bash quickstart.sh --check` (also the no-argument default). Read `savedExposure`, `exposureReadable` and `loopbackInstallAllowed` independently of `ready`: prerequisites can be ready while a saved public tunnel forbids loopback install. `--install` refuses existing `cloudflare`/`cloudflare-quick` before invoking install or changing tunnel policy. Unknown/unreadable/unsafe saved exposure blocks every quickstart action without echoing its contents. Preserve the policy and use the user's explicit intended access; `--public-tunnel` is separate public-access authorization, never an automatic fallback. Preflight success is not a native installation or chat test. [Exposure preflight contract](reference.md#quickstart-exposure-preflight).

Source installation stages and validates code/dependencies, keeps a previous release and reports actual activation/rollback. Reused source is retention, not an update. An installer `success` or live panel means source/service setup only: verify the loaded native engine and a real intended-client send/tool-return/delivered reply separately. Installation does not remint identities, delete existing state, enable paused routines or replay work by default. A native image update, a Custom/Official identity handoff and cross-mode live history/context/session reconciliation are separate operations; none is implied complete. [Installation and privacy boundaries](reference.md#installation).

The installer explicitly invokes `install --official-controls-fallback` and uses `tunnel on --official-controls-fallback --json` for its existing authorized public setup step. Both capture saved raw mode once for desired state and `expectedMode`. Only explicit saved Official with logging enabled and an unchanged unmarked host lacking a unique usable hook can update/start controls without host edits or bounce. `officialLogging: "unavailable-host-hook"` means optional request logging is unavailable; relay it with installer/status success. This differs from `--keep-service`, which retains a healthy listener. Custom/default install, default tunnel and UI save checks stay strict; changed-mode/foreign-listener refusals remain. The flag does not authorize public access or replace exposure preflight. Controls availability proves neither logging nor inference/chat delivery. [Installer fallback and result fields](reference.md#installer-fallback-for-unavailable-official-logging).

## Mode and tunnel

Use `openbot official` or `POST /api/save` with `{"kind":"official"}` for Official. Keep the catalog/secrets. Explicit trimmed Official is a successful guard no-op, independent of provider quota or saved catalog; its tick skips Custom patrol/deferred bounce. Official reconcile stops the Custom guard with self-PID protection.

For separately authorized Official roster repair after a completed remint, inspect `official-dispatch-recovery.py --plan` before an explicit no-flag run. This manual helper requires Official already selected; it does not switch mode or run automatically. Both counterpart IDs converge to one validated owned stock target, unselected counterparts are hidden and sidebar/pin/main preferences are preserved without duplicate self-pairs. Both UUID/server bindings and ownership are checked; the selected target kind must match its journal kind, so a converted plain agent cannot replace a room. Retain every original: this selects a roster, not a live history/SDK/routine merge, delivery proof or permission to prune. [CLI, selection guards and receipts](reference.md#explicit-official-roster-selection). Reuse an owned confirmed Official selection only for its current journal pair after rechecking the Temporal target’s kind, ownership and bindings; an upstream migration of the retained copy does not itself change the confirmed conversation.

Select Custom through a saved model and reconcile; do not infer Custom from an unmarked host or claim a completed identity handoff from save success. A stock host with desired Custom needs checked runtime recovery. Existing live-context/session branches and some native-client mode transitions still need separate verified reconciliation; never resolve them by deleting a branch or silently substituting stock delivery. Guarded repair of missing/corrupt mode requires a valid catalog and raw mode checks before writes/after observation; a changed explicit Official choice wins.

A normal Custom save can select an already enabled trusted local-engine pin before wrap census when the updated native host no longer has the BOX factory. Reconcile checks the complete owned bounded exact-hash stock/wrapped pair, canonical installation wrapper and native runner structure, syntax-checks the candidate and rechecks mode/source/artifact authority before writes. Missing or invalid pins refuse without manufacturing Local or falling back to Temporal. Keep the independently preserved original vendor source for a later Official selection; the composed engine’s `stock.cjs` is not the vendor restore. Do not hand-write mode to make the watcher run. Save success selects routing/runtime bytes, not merged histories, BOX ownership, a loaded process or actual client delivery. [Checked panel engine selection](reference.md#checked-panel-local-engine-selection). The panel’s optional `localEngine` readiness hint is not delivery proof; re-enable retains the saved active model, and explicit save always repeats checks including eager native dependency resolution. [Readiness and dependency limits](reference.md#checked-panel-local-engine-selection).

After validating that pin, a later Custom save preserves an already wrapped current native BOX runner when its wrapper exactly reconstructs for this installation. Legitimate newer post-wrap repairs stay in place; only the installed payload stamp refreshes. The retained pin supplies recovery for unsupported stock or missing BOX execution, not a forced downgrade on every model/key save. Foreign-runtime wrappers and partial marked runners refuse. Ownership, syntax/dependency and mode/source/catalog/payload/artifact checks still apply; preservation is not a new delivery or parity claim. [Current-engine preservation](reference.md#checked-panel-local-engine-selection). Retaining the current engine also keeps recovery’s existing known backup, while the separate exact vendor snapshot remains Official authority; byte-identical vendor snapshot/record files are not rewritten.

When an opted-in Custom recovery already has a completed journal and real verified BOX counterparts, it can reselect those same identities instead of minting another generation from paired originals. All targets must pass actual owner/BOX binding, native roster and full copied-publication checks; current source roles and local plus fresh platform payloads must already be covered before any scheduler/visibility write. Changed roles, uncopied or same-ID divergent history refuse rather than hiding a branch. Selection retires original schedules, preserves target routine/model/effort state and restores recorded preferences under repeated Custom checks. It neither merges live SDK/history state nor proves native admission, delivery, billing or prune safety. An all-Temporal roster is still not local. [Bounded counterpart reuse](reference.md#reuse-existing-box-counterparts-in-custom). Custom reselection and supplemental peer reuse compare transcript owners only; quoted UUIDs/nested tool payloads must remain unchanged. Peer reuse also requires source payload coverage and exact ordered destination publication, with generation/sequence consistency checks and scoped `sourcePayloadsRetained`/`destinationPayloadsPublished` receipts. ID sets or complete-but-divergent blob closures are not live-context/delivery proof. [Peer payload contract](reference.md#supplemental-peer-payload-proof). Separately, reviewed `custom-dispatch-recovery.py --refresh-publication-bindings` refreshes only the owned real-BOX publisher manifest under Custom/local-only and the same dispatch lock; no remint journal, cutover or send is required/performed. Manifest refresh is not native history publication or delivery. [Manifest-only refresh](reference.md#manifest-only-box-publication-authority-refresh).

For an explicitly authorized Local transfer, use the dashboard's Local transfer start/resume controls or `POST /api/local-transfer` with exactly `{"action":"start"}` or `{"action":"resume"}`. Inspect `GET /api/local-transfer` first: `enabled` requires owned literal Custom mode plus Local opt-in, and `available` means the helper exists. `lockHeld` reports lock contention; `workerRunning` additionally requires the recorded worker PID's exact owned transfer-script/root command line. A maintenance keeper or unknown holder leaves the UI locked without claiming a worker or success. Starting never switches mode or enables Local. Status retains a stable `jobId` and derives counts freshly from the owned remint journal. Stale saved `bound-box` derives `copying` for planned entries, `registering` for copied entries or `waiting-for-publication` for registered/all-active entries lacking current exact publication proof. `publicationVerified` requires all current entries active and exact journal/artifact proof; `verifiedAgents` is zero without that proof. The journal remains copying/activation authority. Nontransient failures stop automatic retries at `review-needed`; explicit resume retries all guards without clearing conflicts, accepting merge evidence or creating a conflict override. Keep error bodies private. [Transfer API, commands and retry limits](reference.md#panel-local-transfer-job).

The coordinator checks the complete owned Temporal roster outside all current/historical journal aliases at job start, before activation and before completion. Only proven hidden archives with owned local settings and exact profile/server bindings are excluded. Visible, cloud-only or uncertain sources outside that lineage stop at `review-needed`/`history-conflict`, with safe aggregate counts in the API/card. Existing journal entries remain intact: never reset a generation, auto-append sources or use a local-only copy to discard unseen cloud history/SDK context. Initial planning covers discovered local sources and still blocks unknown cloud-only outsiders; full cloud-history/SDK import is unavailable. Explicit resume reruns the guards. Completion additionally requires `rosterComplete`: zero untracked scope tied to the exact current journal and a `rosterCheckedAtMs` less than 120 seconds old. Missing/expired scope returns saved completion to `checking-bindings` even when publication proof passed. Native delivery and billing remain unverified. [Whole-roster scope](reference.md#whole-owner-roster-transfer-scope).

The optional tool-free transfer advisor reports `diagnosticAssistant` as `running`, `available`, `failed` or `disabled` from its bounded receipt; a missing installed adapter reports `unavailable`. It provides static allowlisted advice without transfer or delivery authority. Do not launch an arbitrary agent, add unbounded inference spend or claim an assistant ran without its actual receipt. Transfer progress, `bound-box` and activation keep native-app delivery/billing verification false; verify those outcomes separately. [Advisor boundaries](reference.md#optional-tool-free-transfer-advisor).

Use `set-expose` / `openbot tunnel on|off|status` for the saved exposure policy. Preserve an existing named connector and its private credentials. Tunnel PID, watcher heartbeat and public health are separate from chat delivery. [Modes and service ownership](reference.md#modes-and-service-ownership).

## Add accounts without replacing another account

Prefer the panel's Add account wizard or `add-provider`, with `familyId`, display `name`, origin and privately supplied credential. It allocates an unused account ID, saves zero models and returns `createdProviderId`, preserving mode/default/models/bot choices. Duplicate display names are allowed; IDs are authority. Orphan secret IDs stay reserved.

Then fetch models for that returned ID, import the requested rows with `upsert-model` and explicitly select one only if authorized. Use `update-provider`/`set-secret` for an existing ID. Legacy `upsert-provider`/`custom` derives an ID from the name and changes mode/default; it is not independent account onboarding.

OpenAI sign-in creates a temporary opaque credential draft; save it through `add-provider` without overwriting another login. Import exactly one selected credential-file account, not its unrelated wrapper. OAuth credentials go only to supported direct OpenAI origins. Keep subscription and API-key accounts separate; exhausted quota does not authorize a paid fallback, relay or account replacement. [Accounts and credentials](reference.md#accounts-and-credentials).

## Models, reasoning and limits

Canonical model IDs are `providerId:slug`; plan wildcard compatibility uses the slug plus provider ID. Preserve same-slug accounts, explicit model protocols, parameters and published metadata. A bot pin wins over the global route; a supported bot/exact-model effort wins over the model's configured effort. Clearing a pin preserves saved effort choices.

Reasoning order is `default · none · low · medium · high · xhigh · max`. Use only the routed model's supported levels; `default` differs from clearing a choice. Default output budget is 65536 with operational ceiling 131072; published output/context metadata is separate and does not authorize raising caps. Do not default to 8192 or force GLM `fast: true`.

Use provider-scoped model discovery/catalog refresh. Do not borrow another origin's protocol/limits or merge accounts. Automatic refresh preserves mode/default, bot choices and existing routes; selected efforts hold an incompatible proposed allow-list. [Model schema and bot overrides](reference.md#models-and-bot-overrides). When authorized to maximize context, set only each existing model row’s `contextTokens` to its verified route/provider published maximum, including million-token windows; keep unknown limits unverified and unchanged. Keep working-window guidance and output budgets separate. In Official, edit the saved plan atomically; `upsert-model`/`use-model` activate Custom. Preserve all other settings; the hop hot-reads the JSON without a host restart. [Context-only procedure](reference.md#maximize-verified-model-context).

## Preserve identities during authorized recovery

Fresh installation does not plan a fleet migration. For a separately authorized legacy migration, the planner captures all actual owned BOX profiles in private `protectedProfiles` keyed by canonical UUID and verification requires each unchanged. It has no built-in working-bot identity. Older `workingProfile` authority must resolve from its saved canonical ID or unique saved server ID; ambiguity fails. Preserve originals, complete history, instructions/routines/tool settings and private session roots. Snapshot/ID checks are not a live context merge or permission to prune duplicates. [Migration authority](reference.md#portable-migration-identity-protection). Future transcript copies normalize only top-level `agentId`; quoted IDs/prose/richText/tool payloads remain distinct evidence, and JSONL partial/unclassified lines stay intact. This prevents future rewriting, not repair of existing history. Matching `latestRootBlobId` metadata is not SDK coverage: verify actual branch root/blob closure and turn/state coverage, preserve divergent roots and never splice/replay/prune from an ID match. [Transcript/context boundaries](reference.md#transcript-ownership-versus-quoted-history).

After an authorized remint's `publish`, inspect the journal's `publicationReloadRequestId` against the private owned `openbot-publication-reload.json`, rather than editing recovery telemetry. The watcher consumes this durable request only with local-only opt-in and Custom selected, checks the exact stable source and native PID/start identity, waits for idle and durably records intent before SIGTERM. If the same process remains after ten seconds, it repeats every authority/idle check before retrying that same target; a replacement is acknowledged without signalling it. Official preserves the request; changed source waits for an authorized `publish` refresh. Do not reset phases or repeatedly invoke `publish` to poll. Replacement acknowledgement still requires separate full ordered publication verification before activation and an intended-client delivery test. [Durable publication reload contract](reference.md#durable-publication-reload).

For per-agent native transcript publication failures, inspect private `openbot-transcript-publication-status.json`. The loaded observer retries the same native publisher lane under current owned BOX manifest and Custom/local-only checks, with at most six retry requests per agent per process and jittered backoff capped at thirty seconds. It never fabricates entries or user turns, rewrites a corrupt ledger, or bounces the host for an individual failure. Official/stop prevents further retries; native success cancels obsolete pending work. Loading changed observer code still needs the existing checked idle reload. `native-drained` and `native-commit-ok` are telemetry, not full publication, UI acknowledgement or reply proof; keep the independent ordered verification and delivery checks. [Publication observer and retry contract](reference.md#native-transcript-publication-observer-and-retries).

For an explicitly authorized return after a completed Local copy was migrated to Temporal, use `init --next-generation --return-from-terminal` to preserve the original stock identity and copy only its recorded terminal descendant into a new Local destination. Divergent branches require a separately prepared and reviewed immutable `accept-history-merge --agent-id <destination-id-from-journal> --receipt <absolute-owned-backup-receipt-path>`; it preserves conflict counts and source evidence instead of bypassing them. Full lineage preferences preserve sections, pins and main selection; selected ancestors’ duplicate routines retire without replaying work or changing unrelated lineages. A later Official roster handoff refuses to hide new merged messages until the original stock counterpart contains them. A receipt neither merges instructions/routines automatically nor proves loaded context, tool execution, client delivery, billing or prune safety. [Terminal-return authority and exact receipt contracts](reference.md#reviewed-terminal-return-and-history-merge-receipts).

The panel transfer coordinator may request one optional tool-free AI diagnostic when deterministic recovery needs review. It uses the currently selected approved route through the owned hop, sends only fixed enums/counts and displays static allowlisted advice. Its private diagnostic file/lock is separate from transfer authority; it cannot merge, activate, change providers or verify delivery. Unsupported/unavailable/failed advice never blocks transfer. Preserve its persisted one-call fingerprint and 15-minute backoff; `openbot-transfer-diagnostics.disable` opts out. [Optional transfer advisor](reference.md#optional-tool-free-transfer-advisor).

## Pauses, routines, ACP and MCP

Use `GET`/`PUT /api/pause` and `/api/pause-bots` rather than hand-editing gateway pause. Ordinary missing/corrupt pause is fail-open; the scheduler conservatively holds malformed pause authority. Official without a logging tap is pure stock, outside OpenBot's gateway pause.

The optional local clock uses the native automation path, native ownership/readiness and shared durable claims. Both-mode policy eligibility does not authorize duplicate platform/local dispatch. Preserve routine enablement/holds/receipts; do not replay missed work, add cron or imitate scheduling with manual user turns. Default concurrency is 2, supported integer range 1–12. [Routine policy](reference.md#routine-policy).

ACP model/thinking choices must be advertised session options and confirmed after selection; preserve saved login/global defaults and original resume cwd. Apply reviewed bridge repairs only to explicitly selected owned sources, with syntax/hash/backup guards and an idle managed reload. MCP discovery/authentication and actual tool execution are separate checks. Never grant extra tools or bypass permission/team policy to make a canary pass. [ACP and MCP](reference.md#acp-and-mcp).
